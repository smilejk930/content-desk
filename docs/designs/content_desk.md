# Content Desk: 확장형 비YMYL 카테고리 및 일상 브이로그 네이버 블로그 자동화 시스템

* **작성자:** smilejk930
* **작성일:** 2026-11-18

## 개요

Content Desk는 단일 작성자가 협찬 유치용 전문 콘텐츠와 개인 브이로그 기록을 병행하기 위해 네이버 블로그에 하루 최대 1건의 글을 작성·스테이징하기 위한 **클라우드 중심(Cloud-First) 하이브리드 시스템**입니다. 카테고리는 **사용자 정의 비YMYL 카테고리 레지스트리 기반 발굴 트랙**과 **개인 기록·브이로그 트랙**으로 이원화해 운영합니다.

1. **전문·협찬 발굴 트랙 (`CategoryProfile` 레지스트리 기반, 기본 프리셋 `테크/IT`):** 사용자가 웹 대시보드에서 비YMYL(Your Money Your Life) 카테고리(`테크/IT`, `여행`, `맛집`, `영화`, `음악` 등)를 직접 추가·수정·삭제하고, 실행 시 원하는 카테고리를 선택해 네이버 검색·데이터랩 API와 Google Trends RSS(설정 시 검색광고 API 선택 연동)로 글감을 발굴·교차 검증합니다.
2. **개인 기록·브이로그 트랙 (`일상/브이로그`):** 트렌드 키워드 발굴을 사용하지 않고, 작성자가 직접 올린 **메모와 실제 사진(최소 1건 필수)**만을 구조화해 개인 일상 기록을 작성합니다. 네이버 블로그 내 별도 게시판(카테고리)으로 분리합니다.

아키텍처는 **무료 플랜(0원) 클라우드 우선 운영을 원칙**으로, **코어 백엔드·웹 대시보드(Cloudflare Pages + Workers 무료 플랜 + Firebase Spark 무료 플랜 Firestore/Auth + Cloudflare R2 무료 플랜)**와 **PC 호스트 전용 `ego-browser` 실행 브리지**로 분리합니다. (로컬 Docker 호스팅 및 외부 API 호출 시 유료 Blaze 전환이 필요한 Firebase Cloud Functions는 배제합니다.)
* **코어 백엔드**는 API 비밀키 보관, 카테고리 프로필, **Firestore(Spark 무료 플랜)** 기반 할당량/영속 원장 관리, 글감 발굴, 무료 티어 LLM·이미지 생성(예: Google AI Studio 무료 티어 일일 상한 제한), 팩트체크 데이터 수집, 검색 순위 추적을 전담하며 **Cloudflare Pages/Workers(무료 플랜, 일 100,000건)**에서 운영합니다.
* **웹 대시보드**는 PC와 휴대폰 모두에서 접속해 카테고리 관리, 글감 선택, 메모·사진 업로드, 팩트체크 승인, 일일 방문자 수 기록을 수행합니다(Firebase Auth 무료 플랜 등 본인 인증 필수).
* **스마트에디터 ONE 임시저장 제어**는 로컬 Windows PC의 `ego-browser` 브리지를 통해서만 동작합니다. 실행 전 접속 기기와 `ego-browser` 설치 여부를 판별하여, **휴대폰 접속 시에는 "PC 환경에서만 가능하다"는 안내**를 표시하고 **미설치 PC에서는 제어 불가 안내와 함께 `ego-browser` 설치 URL을 제공**합니다. 동시에 제어가 불가능한 모든 환경(휴대폰·미설치 PC)에서는 사용자가 직접 복사·붙여넣기로 글을 작성할 수 있도록 **수동 복사 보조 모드**(제목·서식 유지 본문·이미지·태그 분리 복사)를 함께 제공합니다. 대시보드 승인을 통과한 원고만 PC의 `ego-browser`를 통해 네이버 스마트에디터 ONE에 **임시저장**되며, 무인 자동 발행은 영구 제외합니다. 성공 기준은 일일 방문자 수와 검색 순위이며, 실패 기준은 네이버 저품질(`저품질`) 페널티 또는 팩트 오류 발행입니다.

현재 작업 디렉토리 `D:\develop\workspace\content-desk`는 코드, 설정, 스키마 파일이 없는 빈 디렉토리입니다.

### 핵심 기술 제약 및 가드레일

1. **실행 계층 분리 (무료 플랜 클라우드 우선 기준: Cloudflare Pages/Workers + Firebase Spark Firestore + Cloudflare R2 + PC 호스트 전용 `ego-browser` 브리지)**
   * **브라우저 직접 API 호출 불가:** 네이버 OpenAPI(`openapi.naver.com/v1/search/*`, `v1/datalab/*`)는 임의의 브라우저 CORS를 허용하지 않으며 비공개 `X-Naver-Client-Id` / `X-Naver-Client-Secret` 헤더가 필요합니다. Google Trends 역시 브라우저 CORS가 차단됩니다. 따라서 외부 API 호출과 비밀키(Cloudflare Secrets) 관리는 **Cloudflare Workers 코어 백엔드**에서 실행합니다.
   * **무료 플랜 클라우드(Cloudflare + Firebase Spark) 운영 경계:**
     * **외부 API 호출 백엔드 선택:** Firebase Cloud Functions는 외부 네트워크 호출(`openapi.naver.com`, Google Trends)을 위해 유료 Blaze 요금제 전환이 필요하므로 제외하며, 로컬 상시 서버(Docker) 호스팅 역시 배제합니다. 무료 범위에서 외부 API 호출이 가능한 **Cloudflare Pages + Workers(무료 플랜: 일 100,000건 요청)**를 단일 클라우드 백엔드 실행 환경으로 사용합니다.
     * **본인 인증 및 트래픽 보호:** 공개 클라우드 URL에서 타인의 API/LLM 무료 할당량 소진을 막기 위해 **Firebase Auth(Spark 무료 플랜)**(또는 Cloudflare Access 무료 플랜) 본인 인증을 필수로 적용합니다. 또한 클라우드 공용 IP에서는 Google Trends HTTP 429 차단 빈도가 높아지므로 Workers/Firestore 캐시와 지수 백오프를 적용하며, 일시 차단 시에는 네이버 검색·데이터랩만으로 발굴이 지속되도록 설계합니다.
     * **외부 API 및 AI 무료 티어 일일 상한:** 네이버 검색 API(일 25,000건), 데이터랩 API(일 1,000건), 검색광고 API(`/keywordstool`), Google Trends RSS는 모두 무료이며, 원고·도식 이미지 생성 LLM 역시 **무료 티어 제공자(예: Google AI Studio Gemini 무료 티어)**를 기본으로 두고 할당량 원장에서 일일 호출 상한을 엄격히 제한해 과금이 발생하지 않도록 합니다.
     * **`ego-browser` 호스트 실행 필수:** `ego-browser`(`ego-lite`)는 작성자 Windows PC의 GUI 크롬 로그인 프로필(`NID_AUT`/`NID_SES`)을 사용하는 로컬 CLI 도구(`ego-browser nodejs`)이므로, 클라우드 서버 내부에서는 실행할 수 없습니다. 클라우드 백엔드가 기본이지만 `ego-browser` 실행만큼은 **PC에서 스마트에디터 ONE 임시저장을 수행할 때만 구동하는 경량 PC 호스트 브리지**에서 처리합니다.
   * **Firestore Spark 무료 플랜 대체 및 1 MiB 미디어 분리 제약:**
     * SQLite 대신 **Firebase Spark 무료 플랜의 Firestore(저장 1 GiB, 일 읽기 50,000건, 일 쓰기 20,000건 무료)**를 기본 문서 저장소(`CategoryProfile`, `TopicDiscoveryJSON`, `NaverBlogManuscriptBundle`, `PublishReceipt`, 실행 원장, 할당량 원장, 일일 방문자 수)로 사용합니다. 1일 1건 운영 기준이므로 무료 할당량 내에서 운영 가능합니다.
     * Firestore는 문서당 **1 MiB 크기 제한**이 있으므로 사용자 원본 사진과 AI 생성 이미지는 문서에 직접 넣지 않고 **Cloudflare R2 무료 플랜(월 10 GB 저장·무료 egress)**에 저장하며 클라이언트 측 WebP 압축을 적용해 무료 한도 내에 유지합니다. Firestore에는 파일 경로·URL 메타데이터만 저장하고, 스마트에디터 ONE 입력 직전 PC 호스트 브리지가 R2에서 이미지를 로컬 임시 폴더로 내려받아 업로드합니다.

2. **`ego-browser` 설치 여부 및 접속 기기 판별 게이트 + 수동 복사·붙여넣기 보조 모드 (`Fallback UX`)**
   * 대시보드가 모바일과 PC 모두에서 접근 가능해지므로, `스마트에디터 ONE 임시저장 제어` 단계 진입 전에 클라이언트 기기 환경과 로컬 `ego-browser` 상태를 반드시 판별합니다:
     1. **휴대폰·태블릿 등 비PC 환경 접속 시:** 스마트에디터 ONE 제어 버튼을 비활성화(또는 실행 차단)하고 **"스마트에디터 ONE 제어는 PC 환경에서만 가능합니다."** 알림을 표시합니다. 휴대폰에서는 글감 선택, 메모·사진 업로드, 원고 생성, 팩트체크 승인 후 Firestore 대기열에 저장해 PC에서 이어갈 수 있으며, 즉시 작성할 수 있도록 수동 복사 보조 모드를 함께 노출합니다.
     2. **PC 접속 시 `ego-browser` 미설치/미감지 상태:** 대시보드가 로컬 호스트 브리지 헬스체크(`127.0.0.1`)를 통해 `ego-browser` 설치 및 브리지 구동 여부를 확인합니다. 응답이 없거나 미설치 상태이면 **"PC에 `ego-browser`가 설치되어 있지 않아 스마트에디터 ONE 제어가 불가능합니다."** 알림과 함께 **`ego-browser` 설치 URL 및 실행 안내**, 그리고 수동 복사 보조 모드를 표시합니다.
     3. **`ego-browser` 설치 확인된 PC:** 승인된 `NaverBlogManuscriptBundle`을 로컬 호스트 브리지로 전달해 스마트에디터 ONE 임시저장 작업을 실행합니다.
   * **수동 복사·붙여넣기 보조 모드 (`Fallback UX`) 설계 제약:** 스마트에디터 ONE은 마크다운 문법(`##`, `**`)을 일반 문자로 취급하고 HTML 내 외부 이미지 핫링크(`<img src="...">`)를 차단·누락시키므로, 텍스트와 이미지를 분리해 복사해야 합니다:
     * `[제목 복사]`: 권장 게시판명 및 공개 범위(`전체공개`/`이웃공개`) 안내와 함께 제목 클립보드 복사.
     * `[서식 유지 본문 복사]`: `ClipboardItem` API(`text/html` + `text/plain`)로 소제목·굵게·목록·인용구 서식, 공정위/AI 활용 표시 문구, 그리고 **`[📷 이미지 N 삽입 위치: 캡션]`** 마커를 함께 복사.
     * `[이미지 개별 복사(PC) / 저장(모바일·PC)]`: PC 사용자는 개별 이미지를 클립보드에 복사해 에디터에 `Ctrl+V`로 업로드하고, 모바일 사용자는 기기에 저장해 네이버 블로그 앱 사진첩에서 첨부.
     * `[태그 일괄 복사]` 및 `[네이버 블로그 글쓰기 열기]` 바로가기 제공(수동 완료 후 대시보드에서 발행 URL/`logNo`를 수동 등록해 검색 순위 추적을 연결할 수 있도록 지원).

3. **사용자 정의 비YMYL 카테고리 레지스트리 및 `C-Rank` 분산 방지 가드레일**
   * 작성자가 추후 `여행`, `맛집` 등으로 콘텐츠를 확장할 수 있도록, 웹 대시보드에서 비YMYL 카테고리를 **추가·수정·삭제(CRUD)** 하고 글감 발굴 실행 시 대상 카테고리를 **선택**할 수 있는 `CategoryProfile` 레지스트리를 제공합니다(초기 기본 프리셋은 `테크/IT`).
   * 각 `CategoryProfile`은 Firestore에 아래 필드를 정의합니다:
     * `category_id`: 내부 식별자
     * `display_name`: 대시보드 표시명 (예: `테크/IT`, `여행`, `맛집`)
     * `naver_board_name`: 스마트에디터 ONE에서 매핑할 네이버 블로그 게시판명
     * `datalab_anchor_keyword`: 데이터랩 배치 간 `0-100` 상대 비율 정규화를 위한 카테고리별 고정 기준 키워드 (미입력 시 카테고리 생성·실행 불가)
     * `seed_keywords`: 초기 발굴·연관 검색용 시드 키워드 목록
     * `default_media_policy`: 카테고리별 기본 미디어·근거 정책 (예: `여행`·`맛집` 같은 현장 경험 카테고리는 실제 사진·메모 최소 1건 필수, `테크/IT`는 실사용 후기 트랙과 출처 기반 개념 해설 트랙 모두 지원)
   * **하드 YMYL 차단 목록(Blocklist):** 카테고리 생성과 키워드 발굴 요청 시 백엔드 검증기가 **주식·금융·투자·암호화폐·의료·건강·법률** 관련 카테고리명 및 시드 키워드를 강제 거부합니다.
   * **`C-Rank` 분산 경고 가드레일:** 블로그 운영 초기에 여러 카테고리를 무분별하게 번갈아 발행하면 네이버 `C-Rank` 주제 집중도 형성이 지연됩니다. 대시보드는 카테고리별 누적 발행 건수 및 최근 발행 비중을 추적하여 설정된 분산 임계치를 넘길 경우 경고를 표시하고, 각 카테고리를 스마트에디터 ONE의 분리된 블로그 게시판에 매핑합니다.
   * **개인 기록·브이로그 트랙(`일상/브이로그`) 병행:** 외부 트렌드 발굴을 타지 않는 순수 일상 기록 모드도 함께 유지합니다. 별도 게시판으로 매핑하며 대시보드에서 공개 범위(`전체공개` 또는 `이웃공개`)를 선택할 수 있습니다.
   * **법규 및 협찬 표시:** 협찬 포스팅(`is_sponsored=true`) 작성 시 공정거래위원회 **추천·보증 심사지침**에 따라 제목 또는 본문 최상단에 경제적 이해관계 표시 문구를 강제 삽입하고 검증합니다.

4. **글감 발굴 및 검색 수요 측정 (선택된 카테고리 기준 파이프라인 + 선택형 검색광고 어댑터)**
   * 사용자가 대시보드에서 특정 `CategoryProfile`을 선택하면 코어 백엔드가 해당 카테고리의 `seed_keywords`와 `datalab_anchor_keyword`를 사용해 교차 검증을 실행합니다.
   * 네이버 데이터랩(`POST /v1/datalab/search`, 일 1,000건 한도, 호출당 최대 5개 `keywordGroups`)은 배치 내 `0-100` 상대 비율만 반환하므로 선택된 카테고리의 `datalab_anchor_keyword`를 항상 포함해 호출하고 결과를 24시간 이상 Firestore에 캐시합니다.
   * 네이버 검색 API(`blog.json`, `news.json`, 일 25,000건 한도)는 선택된 카테고리 후보 키워드의 문서 공급량(`total`)과 스니펫을 수집하며, 한국 Google Trends는 서버 측 캐시 기반 `https://trends.google.com/trending/rss?geo=KR`를 보조 시드로 사용합니다.
   * **네이버 검색광고 API(`GET https://api.searchad.naver.com/keywordstool`, HMAC-SHA256 서명)**는 선택형 플러그인 어댑터로 구성합니다. API 키 미설정 시 기본 파이프라인(검색·데이터랩·Google Trends RSS)으로 동작하고, 키 설정 시 월간 PC/모바일 절대 검색량과 경쟁도(`월간 검색량 / 블로그 문서 수`) 기회 점수를 자동 산출합니다.

5. **카테고리 정책별 미디어·팩트체크 및 저품질 예방 게이트**
   * **현장 경험 카테고리(`여행`, `맛집`) 및 `테크/IT` 후기·실사용 글:** 방문하지 않은 장소나 사용하지 않은 제품에 대한 허위 후기는 `저품질` 및 팩트 오류의 직접 원인입니다. 따라서 작성자의 실제 사진(EXIF 보존 및 개인정보 위치 태그 제거 옵션 포함) 또는 직접 작성한 실사용 메모를 **최소 1건 필수**로 요구하며, AI 생성 이미지가 음식·장소·제품 실물 사진을 대체하는 것을 금지합니다.
   * **`테크/IT` 개념·트렌드 해설 글:** 사용자 메모가 없는 날에도 작성을 허용하되, 본문의 모든 수치·제품 스펙·가격·날짜·사실 주장은 수집된 1차 출처 URL 및 스니펫에 근거해야 합니다. AI 생성 이미지는 편당 최대 1~2장의 개념 설명/도식 이미지로만 허용하며 **AI 활용 표시**를 필수로 포함합니다.
   * **`일상/브이로그` 개인 기록 글:** 작성자 실사·메모(최소 1건 필수)만 사용하며 AI 생성 이미지를 금지합니다. 메모에 없는 장소·일시·경험을 AI가 임의로 덧붙이지 않도록 제약합니다.
   * 모든 트랙의 원고는 스마트에디터 ONE 입력 전 웹 대시보드에서 **검증 게이트**(미검증 주장 `[VERIFY]` 표시, 출처 URL 목록, 과거 발행 글 및 SERP 대비 N-gram 유사도 경고, 일일 상한 `<= 1건/일` 원장 확인)를 통과해 사용자의 명시적 승인을 받아야 합니다.

6. **스마트에디터 ONE 임시저장 전용 드라이버 및 `task.handOff()` 복구**
   * 네이버 공식 블로그 글쓰기 API는 2020년 5월 종료되었으므로 PC 호스트의 `ego-browser`를 통해 `#mainFrame` iframe 내 `.se-component` 블록을 조작합니다.
   * 기존 임시저장 복구 모달(`작성 중인 글이 있습니다`) 감지, 선택된 `CategoryProfile.naver_board_name`(또는 `일상/브이로그`) 게시판 선택, Cloudflare R2에서 내려받은 로컬 이미지를 CDP `DOM.setFileInputFiles`로 업로드 후 `phinf.pstatic.net` 노드 마운트 대기, 사전 셀렉터 점검(canary) 실패 시 중단 로직을 포함합니다.
   * `ego-browser`는 사용자 브라우저 프로필 쿠키 저장소를 공유하므로 쿠키/캐시 삭제 명령은 금지합니다. 세션 만료, 2단계 인증, CAPTCHA 발생 시 즉시 `AUTH_REQUIRED` / `CAPTCHA_DETECTED` 상태로 멈추고 `task.handOff()`를 통해 사용자가 직접 로그인을 완료한 뒤 재개합니다.
   * 무인 자동 발행은 영구 제외되므로 자동화는 항상 `임시저장` 완료 및 저장 URL/스크린샷 기록(`PublishReceipt`)에서 종료되며, 최종 발행(및 필요 시 공개 범위 확인)은 사용자가 스마트에디터 ONE에서 직접 클릭합니다.

7. **영속 원장(Firestore), 관측성 및 성과 지표 추적 경계**
   * 모든 실행은 `run_id`, `topic_id`, `track` (`category_discovery` | `personal_vlog`), `category_id`, 멱등성 문서 ID/트랜잭션 키(`date + category_id`)를 기준으로 **Firestore**에 기록해 재실행 시 중복 초안 생성을 막고, API 할당량 원장과 LLM/이미지 호출 상한을 관리합니다.
   * **검색 순위 및 색인 여부**는 발굴 트랙 발행 URL(`logNo`)과 타겟 키워드 기준으로 네이버 검색 API(`blog.json`)를 통해 백엔드가 자동 추적합니다.
   * **일일 방문자 수**는 네이버 크리에이터 어드바이저 공식 REST API 부재에 따라 대시보드에 사용자가 직접 입력해 Firestore에 기록합니다.

### 핵심 설계 딜레마 및 해결 방식

* **딜레마 1 — 무료 클라우드·모바일 우선 운영 vs. API 보안, 유료 플랜 회피 및 `ego-browser` PC 종속성:**
  * *해결 방식 (클라우드 코어 + 경량 PC 브리지 분리):* 외부 API 호출·비밀키·원고 생성은 무료 범위에서 아웃바운드 API 호출이 가능한 **Cloudflare Pages/Workers(무료 플랜)**에 두고, DB·인증은 **Firebase Spark 무료 플랜(Firestore·Auth)**을 사용하며, 이미지는 **Cloudflare R2(무료 10 GB) + WebP 압축**으로 분리합니다. 로컬 Docker 상시 백엔드는 배제하고, 스마트에디터 ONE 제어 시에만 PC 호스트 `ego-browser` 브리지를 호출하며 미지원 환경에서는 수동 복사 보조 모드를 제공합니다.
  * *부수적 관리 비용:* 클라우드 본인 인증 설정, 무료 티어 일일 할당량(Firestore 읽기/쓰기, Workers 요청, 무료 AI API 상한) 모니터링, PC 임시저장 시에만 경량 `ego-browser` 브리지 실행 관리가 필요합니다.
  * *달성 목표:* 별도 로컬 상시 서버(Docker)나 인프라 요금(0원) 없이 휴대폰·PC 어디서나 대시보드에 접근하고, 비밀키 노출 없이 PC에서만 안전하게 스마트에디터 ONE 임시저장을 실행합니다.

* **딜레마 2 — 멀티 카테고리 확장(`테크/IT`, `여행`, `맛집` 등) 및 브이로그 vs. `C-Rank` 주제 집중도 및 저품질 회피:**
  * *해결 방식 (카테고리별 규칙 분리 및 사전 차단):* `CategoryProfile`로 카테고리별 기준 키워드(`datalab_anchor_keyword`), 네이버 블로그 게시판 매핑, 미디어 정책(`여행`/`맛집` 실사 필수 vs. `테크/IT` 개념 해설 허용)을 각각 격리하고, YMYL 차단 목록으로 등록 시점부터 위험 분야를 막으며, 대시보드에 `C-Rank` 분산 경고를 표시합니다.
  * *부수적 관리 비용:* 새 카테고리를 추가할 때 기준 키워드·게시판명·미디어 정책을 함께 설정해야 하며, 게시판 수 증가에 따른 발행 균형 판단은 작성자가 관리합니다.
  * *달성 목표:* 원하는 카테고리를 자유롭게 추가·선택해 발굴하면서도 각 분야의 진정성 기준과 `C-Rank` 분산 여부를 한눈에 통제할 수 있습니다.

* **딜레마 3 — 일일 포스팅 지속성 vs. 사실 정확성 및 1차 경험 진정성:**
  * *해결 방식 (원본 출처 사전 확보 및 미검증 초안 격리):* 발굴 트랙은 원고 작성 전에 1차 출처 본문을 미리 저장해 근거를 연결하고, 경험 카테고리(`여행`, `맛집`, `테크/IT` 후기) 및 `일상/브이로그`는 실사·메모가 없으면 생성 자체를 막습니다. 하루 1건은 의무 발행량이 아닌 상한(`<= 1건/일`)으로 둡니다.
  * *부수적 관리 비용:* 출처 스냅샷 저장소, 카테고리 정책별 검증 분기, 대시보드 내 보류 초안 검토 대기열 관리가 필요합니다.
  * *달성 목표:* 모든 원고가 확보된 출처 또는 실제 사용자 메모·사진에 연결되어 근거 없는 내용이 스마트에디터에 입력되지 않습니다.

* **딜레마 4 — 브라우저 에디터 자동화 vs. 화면 구조(DOM) 변경 및 봇 탐지 리스크:**
  * *해결 방식 (사전 자가 점검 및 임시저장 단계 분리):* 입력 시작 전에 스마트에디터 ONE 로그인 상태와 핵심 화면 요소를 먼저 점검하고, 자동화는 임시저장까지만 수행해 최종 발행 판단과 클릭은 사람에게 남깁니다.
  * *부수적 관리 비용:* 하루 1회 작성자가 PC의 스마트에디터 ONE에 접속해 최종 발행 버튼을 직접 눌러야 합니다.
  * *달성 목표:* 네이버 에디터 구조가 바뀌거나 업로드가 어긋나도 공개 발행 사고로 번지지 않고 임시저장 단계에서 안전하게 멈춥니다.

## 목표 및 제외 범위

* **포함 목표 (1단계 구현 범위):**
  * **무료 플랜 클라우드 우선 백엔드(Cloudflare Pages + Workers 무료 플랜) + Firebase Spark(Firestore·Auth 무료 플랜) + Cloudflare R2(무료 10 GB + WebP 압축) + PC 호스트 `ego-browser` 브리지** 아키텍처를 구축하고, 무료 티어 AI/API 일일 호출 상한을 강제합니다.
  * **`ego-browser` 설치 여부 및 기기 판별 게이트 + 수동 복사·붙여넣기 보조 모드(`Fallback UX`)**를 제공합니다(휴대폰 접속 시 "PC 환경에서만 가능" 알림, `ego-browser` 미설치 PC 시 "스마트에디터 ONE 제어 불가" 알림 및 설치 URL 제공, 제어 불가 환경에서는 제목·`ClipboardItem text/html` 서식 유지 본문·이미지 복사/다운로드·태그 복사 패널 제공).
  * **사용자 정의 비YMYL 카테고리 레지스트리(`CategoryProfile`)**를 제공합니다(기본 프리셋 `테크/IT` 외 `여행`, `맛집` 등 CRUD·선택, 카테고리별 `naver_board_name`·`datalab_anchor_keyword`·`seed_keywords`·`default_media_policy` 정의, `C-Rank` 분산 경고 표시).
  * **`일상/브이로그` 개인 기록 트랙**을 함께 지원합니다(별도 블로그 카테고리, 트렌드 API 미사용, 사용자 실사·메모 최소 1건 필수, AI 이미지 금지, 공개 범위 `전체공개`/`이웃공개` 선택 지원).
  * 채널 중립적 리서치·소재 JSON(`TopicDiscoveryJSON`)과 1단계 네이버 출력 스키마(`NaverBlogManuscriptBundle`)를 분리해 Firestore에 영속 저장합니다.

  * `ego-browser`로 스마트에디터 ONE **임시저장까지만 자동화**하고, 발행 후 **네이버 검색 API 기반 검색 순위·색인 자동 추적** 및 **대시보드 방문자 수 기록**을 제공합니다.

## 검토한 대안 및 기각 사유

* **웹브라우저에서 네이버/구글 API를 직접 호출하는 순수 브라우저 앱:** 네이버 OpenAPI의 CORS 미지원 및 `Client-Secret` 노출 문제, Google Trends의 브라우저 CORS 차단, 브라우저 JS의 로컬 `ego-browser` 실행 불가로 인해 기각됨(코어 백엔드 + 웹 대시보드 + PC 호스트 `ego-browser` 브리지 구조로 대체).
* **SQLite 로컬 단일 DB 고정 vs. Firestore Spark 무료 플랜(+ Cloudflare R2 무료 플랜):** 클라우드 중심 운영과 다중 기기 접근을 위해 SQLite 단일 파일 대신 **Firebase Spark 무료 플랜 Firestore** 컬렉션 구조로 대체함(1 MiB 제한 및 무료 용량 유지를 위해 이미지 바이너리는 WebP 압축 후 Cloudflare R2 무료 플랜으로 분리).
* **Firebase Cloud Functions 백엔드 사용 (무료 제약으로 기각됨):** Firebase Spark(무료) 플랜에서는 Cloud Functions의 외부 네트워크 아웃바운드 호출이 차단되어 유료 Blaze 요금제 전환이 필수이므로, 무료 플랜에서 외부 API 호출을 지원하는 **Cloudflare Pages/Workers(무료 플랜)**를 클라우드 백엔드로 선택함.
* **작성자 기각: 로컬 Docker 컨테이너 기반 백엔드 호스팅.** 기본 운영 형태를 클라우드 아키텍처로 두기 위해 로컬 Docker 백엔드를 제외하고 Cloudflare Pages/Workers + Firebase Spark 클라우드 스택을 채택함(PC 호스트의 `ego-browser`는 스마트에디터 ONE 제어 시에만 사용하는 경량 로컬 브리지로 한정).
* **미설치 PC·모바일에서 `ego-browser` 실패를 단순 에러로만 노출하거나 마크다운 원문 복사만 제공하는 방식:** 사용자가 원인을 알 수 없고 마크다운 기호 깨짐 및 외부 이미지 누락이 발생하므로, 기기·브리지 판별 안내(모바일 "PC 전용", 미설치 PC "제어 불가 + 설치 URL")와 함께 **`ClipboardItem text/html` 서식 본문 + 이미지 분리 복사·다운로드 보조 모드**를 제공하도록 결정함.
* **작성자 기각: `테크/IT` 단일 카테고리만 고정해 다른 비YMYL 주제를 추가할 수 없는 방식.** 추후 `여행`, `맛집` 등 다른 비YMYL 주제와 개인 브이로그로 확장해야 하므로 사용자 정의 비YMYL 카테고리 레지스트리 + `일상/브이로그` 트랙으로 전환함.
* **작성자 기각: 무코드 0단계 검증 또는 웹 UI 없는 CLI 전용 워크플로우.** 대시보드 기반 카테고리 관리·메모/사진 첨부·팩트체크 승인·방문자 기록을 위해 웹 대시보드 + 백엔드 구축을 선택함.
* **작성자 기각: "주식" 등 YMYL 카테고리 포함 및 모든 글의 무제한 AI 이미지 허용.** YMYL은 영구 차단하고, 현장 경험(`여행`, `맛집`, 제품 후기, 브이로그)은 실사·메모 필수, `테크/IT` 개념 해설 글만 AI 도식 이미지(+ AI 활용 표시)를 허용함.
* **작성자 기각: 초기부터 네이버 검색광고 API(`/keywordstool`)를 필수 강제하거나 완전히 배제하는 방식.** 기본 파이프라인 + 선택형 검색광고 API 플러그인 구조로 결정함.
* **작성자 기각: 2단계 무인 자동 발행 전환.** 무인 자동 발행을 영구 제외하고 임시저장 후 수동 최종 발행 모델을 확정함.

## 핵심 확정 사항 및 다음 단계 준비

정식 설계 문서(`/egm-draft`) 작성 시 아래 확정된 결정 사항과 1단계 계약을 그대로 반영합니다.

1. **확정 아키텍처 (무료 플랜 클라우드 우선: Cloudflare + Firebase Spark + PC 호스트 브리지):**
   * **코어 백엔드(Cloudflare Pages + Workers 무료 플랜):** API 프록시, 비밀키 관리, 카테고리 레지스트리, 무료 티어 LLM·이미지 생성 호출(일일 상한 적용), 순위 추적. (Firebase Auth 무료 플랜 등 본인 인증 필수, 로컬 Docker 및 유료 Blaze 전환이 필요한 Firebase Cloud Functions 제외)
   * **데이터 저장소:** **Firebase Spark 무료 플랜 Firestore**(문서·원장·카테고리·방문자 수) + **Cloudflare R2 무료 플랜**(WebP 압축 사진·AI 이미지 바이너리 분리 저장).
   * **로컬 실행기:** PC에서 스마트에디터 ONE 임시저장을 실행할 때만 사용하는 Windows 호스트 `ego-browser` 브리지(`127.0.0.1`).
2. **확정 `ego-browser`·기기 판별 UX 및 수동 복사 보조 모드:** 임시저장 실행 전 접속 기기와 로컬 `ego-browser` 설치 여부를 점검해, 휴대폰에서는 "PC 환경에서만 가능" 안내, `ego-browser` 미설치 PC에서는 "스마트에디터 ONE 제어 불가" 알림 및 설치 URL을 제공합니다. 제어 불가 환경에서는 `[제목 복사]`, `[서식 유지 본문 복사(text/html + 이미지 위치 마커)]`, `[이미지 개별 복사/다운로드]`, `[태그 복사]`, `[블로그 글쓰기 열기]` 수동 복사 모드를 함께 제공합니다.
3. **확정 카테고리 및 트랙 분리 모델:**
   * **확장형 비YMYL 발굴 트랙 (`CategoryProfile` CRUD):** 초기 프리셋 `테크/IT` 외에 `여행`, `맛집` 등 비YMYL 카테고리를 추가·삭제·선택해 발굴·교차 검증합니다(`naver_board_name`, `datalab_anchor_keyword`, `seed_keywords`, `default_media_policy` 포함, `C-Rank` 분산 경고 표시).
   * **개인 기록 트랙 (`일상/브이로그`):** 별도 블로그 카테고리, 트렌드 발굴 미사용, 사용자 메모·실제 사진(최소 1건 필수), `전체공개`/`이웃공개` 선택 지원.
   * **영구 제외:** 주식·금융·암호화폐·의료·법률 등 YMYL 분야.
4. **확정 편집 및 미디어 정책:** `여행`·`맛집`·`테크/IT` 후기·`일상/브이로그` 글은 사용자 실사·메모 최소 1건 필수(AI 대체 이미지 금지). `테크/IT` 개념·트렌드 해설 글만 AI 도식 이미지(편당 최대 1~2장, AI 활용 표시 필수) 허용. 협찬 시 공정위 경제적 이해관계 표시 검증 필수.
5. **확정 발굴 스키마, 발행 경계 및 지표 추적:** 2티어 JSON(`TopicDiscoveryJSON` + `NaverBlogManuscriptBundle`)을 Firestore에 저장하고, 기본 발굴 파이프라인 + 선택형 검색광고 API(`/keywordstool`) 플러그인을 결합합니다. **무인 자동 발행은 영구 제외**하며 `ego-browser` 임시저장 후 작성자가 직접 최종 발행합니다. 검색 순위·색인은 네이버 검색 API로 자동 추적하고, 일일 방문자 수는 대시보드에 기록합니다.
